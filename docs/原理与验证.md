# 原理与验证

日期：2026-10-08　对象：STM32CubeMX（安装于 `C:\stm32mx软件`，自带 Temurin JDK 21.0.3）

## 1. 为什么不能像别的项目那样改文件

排查结论：

| 检查项 | 结果 |
|---|---|
| 资源包机制 | **无**。全部插件 jar 内 `com/st/microxplorer/**` 只有 `Plugin.properties`（插件元数据），没有任何 `messages*.properties` / `bundle*.properties` |
| 界面文字在哪 | **硬编码在 class 常量池**。例：`pinoutandconfiguration.jar` 里直接能看到 `Save As CSV File`、`Alternate Function`、`Generate CSV pinout text file` 等串 |
| UI 框架 | **Swing/AWT**（插件里引用 `javax/swing` 的类 2398 个、`java/awt` 3583 个；`org/eclipse/swt` 为 **0**）；`power.jar` 带 jfreechart、`projectmanager.jar` 带 l2fprod，均为 Swing 组件库 |
| 主程序位置 | 打包在 `STM32CubeMX.exe`（227 MB）内部；文件尾部为加密/混淆数据（非标准 zip EOCD），**无法安全改写** |
| 启动方式 | `STM32CubeMX.exe` 是壳，实际执行：`jre\bin\javaw.exe <STM32CubeMX.l4j.ini 的参数> -classpath "STM32CubeMX.exe;anything" com.st.microxplorer.maingui.STM32CubeMX` |

因此「改 jar / 改 exe」这条路要么不可行、要么破坏完整性且补丁复杂——与「不影响运行」的要求冲突。

## 2. 采用的方案：运行时翻译（Java Agent）

### 2.1 可行性验证

在 `STM32CubeMX.l4j.ini` 里加 `-javaagent:...` 后，从进程命令行确认参数确实传给了 JVM；
用最小 agent 探针验证 `premain` 被调用（写入标记文件成功）。

### 2.2 工作机制

```
premain → 读词库（与 agent 同目录的 zh.tsv）
       → 起一个守护线程，每 400ms 在 Swing 事件线程（EDT）上执行一轮遍历
```

每轮遍历 `Window.getWindows()` 中所有**可见**窗口，递归处理：

| 类型 | 处理内容 |
|---|---|
| `JFrame` / `JDialog` / `Frame` / `Dialog` | 标题（支持 `*` 短语替换，如 `Untitled`→`未命名`） |
| `JMenu` | **显式遍历其 `JPopupMenu`**（菜单项不在组件子节点里，必须单独进去，否则菜单翻不到） |
| `AbstractButton`（含 `JMenuItem`/`JCheckBox`/`JRadioButton`） | 文本 |
| `JLabel` | 文本 |
| `JComponent` | tooltip、`TitledBorder` 标题、弹出菜单 |
| `JTabbedPane` | 每个页签标题 |
| `JTable` | 表头列名 |
| `JInternalFrame` | 标题 |

命中的字符串来自**精确匹配**词库（另含去首尾空白、去结尾 `:`/`...`、HTML 标签内文字分段翻译三种回退）。
所有替换只调用 `setText` / `setTitle` / `setToolTipText` 等**显示接口**——不修改任何模型、数据或业务状态，
因此不可能影响运行结果。遍历用 `visited` 集合防环，全程 `try/catch` 吞异常，绝不干扰主程序。

### 2.3 安全边界

- **不翻译**：下拉框/列表/表格单元格数据、输入框内容、自绘画布文字——避免碰数据；
- 词典里也没有器件型号、工具链名（`MDK-ARM V5`、`EWARM V9`）等**应保留英文**的技术名词；
- 未命中 → 原样英文，不会空白或乱码。

## 3. 实测记录

1. **agent 加载**：启动后进程命令行含 `-javaagent:...`；`premain` 日志正常。
2. **主页汉化**（桌面快捷方式启动，截图核验）：
   - 标题栏：`STM32CubeMX 未命名`
   - 菜单栏：`文件`、`窗口`、`帮助`
   - 主页：`现有工程`、`打开现有工程`、`新建工程`、`我要：`、`从 MCU 开始创建工程`、`进入 MCU 选型`、`从 ST 开发板开始创建工程`、`进入开发板选型`、`从示例开始创建工程`
3. **菜单项收集**：收集模式抓到 `新建工程 ...`、`加载工程 ...`、`导入工程 ...`、`工程另存为 ..`、`退出`、`生成报告`、`刷新数据`、`检查更新`、`管理嵌入式软件包` … 等菜单项，均已入词库。
4. **还原**：`还原英文.cmd` 从 `.zhbak` 恢复后启动为英文。

### 过程中修掉的两个坑（对后续维护有用）

1. **匿名内部类必须一起打包**：agent 里用了匿名 `Runnable`，若 `jar` 只打包 `Stm32CubeMxZhAgent.class`，
   加载内部类时 `NoClassDefFoundError` 被 `premain` 的兜底 `catch` 吞掉，表现为「agent 装了但毫无反应」。
   构建脚本已改为打包整个 classes 目录（并保留 `agent-error.txt` 作为兜底诊断）。
2. **`.ps1` 必须带 UTF-8 BOM**：本机 Windows PowerShell 5.1 按 ANSI(GBK) 读取无 BOM 的脚本，
   中文会变成乱码并导致**语法错误**；`.cmd` 则相反，须用 GBK/ANSI 保存，否则批处理解析不了中文路径。
